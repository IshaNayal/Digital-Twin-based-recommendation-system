# Digital-Twin-based-recommendation-system
Digital Twin-based recommendation system for ICU patients using eICU Collaborative Research Database Demo. Creates patient embeddings, finds similar “twins,” and uses their outcomes to predict risks and suggest personalized treatments. Combines time-series modeling, similarity learning, and explainable AI for clinical decision support.


The pipeline for building a Digital Twin-based recommendation system using the eICU dataset starts with collecting and organizing raw ICU data into a usable format. The dataset contains multiple tables such as patient demographics, vital signs, lab results, medications, and diagnoses, so the first step is to merge these sources into a unified patient-level dataset. This involves aligning time-series data (like heart rate, blood pressure) with static features (like age, gender, diagnosis) and handling missing values using techniques like forward filling or mean imputation. The goal of this stage is to convert raw ICU records into clean, structured inputs that represent each patient’s clinical condition over time.

Once the data is prepared, the next step is to create patient embeddings, which are compact numerical representations of each patient’s state. Since ICU data is time-dependent, models like LSTM or Transformer encoders are used to process sequences of vital signs and lab measurements, capturing temporal patterns such as deterioration or recovery. These models learn to encode each patient into a fixed-length vector that summarizes their entire clinical trajectory. This embedding acts as the “digital twin identity” of the patient.

After generating embeddings, the system performs similarity learning to identify “digital twins.” For a given patient, similarity metrics like cosine similarity or K-nearest neighbors (KNN) are used to find past patients with the most similar embeddings. These similar cases represent patients who had comparable medical conditions and trajectories. This step is crucial because it connects the current patient to historical outcomes and treatments, forming the foundation of personalized recommendations.

Next comes the recommendation and prediction module, where the system leverages the identified twins. It analyzes the treatments given to these similar patients and their corresponding outcomes, such as survival or recovery time. Based on patterns observed in these historical cases, the system suggests treatments that were most effective for similar patients. At the same time, predictive models like logistic regression or XGBoost can be applied on embeddings to estimate risks such as mortality or prolonged ICU stay. This dual approach enables both decision support (what to do) and risk assessment (what might happen).

Finally, the pipeline integrates explainable AI using LLMs to make the system interpretable. Instead of just outputting predictions or recommendations, the model generates human-readable explanations. For example, it can explain that a patient is similar to a group of past ICU cases with a certain condition, and that a specific treatment led to better outcomes in those cases. This step is critical in healthcare settings, where transparency and trust are essential for clinical adoption.

Overall, the pipeline flows from raw ICU data → preprocessing → patient embeddings → similarity-based digital twins → treatment recommendation and risk prediction → explainable outputs, forming a complete end-to-end intelligent clinical decision support system.
